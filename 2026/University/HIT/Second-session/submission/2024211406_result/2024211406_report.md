## 三、方案说明

### 3.1 设计思路

**TilingData 设计（任务一）**：
`QmmCustomTilingData { TCubeTiling cubeTilingData; uint32_t isPertoken; uint32_t workspaceSize; uint32_t m, n, k, singleCoreM, singleCoreN; }`。`CalcQmmTiling` 用 `MultiCoreMatmulTiling`（A: ND INT8、B: NZ INT8、C: ND INT32）求解 base 分块与多核切分，求解失败退回 128×128 单核兜底；并按 baseM/baseN 重算对齐后的核间切分边界（保证 NZ 列偏移与 C 写地址一致）；host 侧以 `(isPertoken, M, N, K)` 为 key 用 `std::map` 缓存 tiling 结果。

**Cube-only Kernel（任务二）**：`QmmCubeBasicKernel` 纯 AIC，Matmul 配置关闭 `enUnitFlag`（AIC 上无 UB，开启 UnitFlag 同步非法），`SetOrgShape/SetSingleShape/SetTensorA/SetTensorB` 后一次 `IterateAll` 直写 INT32 输出。

**Cube+Vector 混核 Kernel（任务三）**：`QmmPertokenKernel` 以 `__mix__(1, 2)` 启动，AIC 将 INT32 结果写 GM workspace，`CrossCoreSetFlag<2,PIPE_FIX>(5)` / `CrossCoreWaitFlag<2,PIPE_S>(3)` 与 AIV 握手；AIV 按 N 方向 1024 条带在 2 个 AIV 核上交错执行 `AscendDequant`（per-channel）→ `Muls`（per-token）→ `Cast(CAST_RINT)` 转 BF16 写回，再 `SetFlag<2,PIPE_MTE2>(3)` 通知 AIC 复用 workspace。数据流：

```
x1(ND int8) ─┐
             ├─ AIC Matmul ─> workspace(GM int32) ─> AIV Dequant×Scale ─> Cast ─> y(BF16)
x2(NZ int8) ─┘                        ▲ per-channel scale / per-token scale
```

### 3.2 问题解决与优化策略

1. **遇到的问题与解决**：
   - *N=6144 等大 N 输出错位*：`MultiCoreMatmulTiling` 给出的分块未按 base 对齐导致 `singleCoreN=615` 一类取值，NZ 物理列偏移与 C 写地址错位；改为按 baseM/baseN 重算对齐核间切分后解决。
   - *AIC 纯 Cube 分支崩溃*：`CFG_NORM` 默认 `enUnitFlag=true`，在 AIC 上访问不存在的 UB；显式关闭后正常。
   - *端到端时延异常偏高*：decode 每生成 1 token 调用算子 252 次，host 端每次重跑 tiling 求解成为瓶颈；引入 `(isPertoken,M,N,K)` tiling 缓存后消除。
   - *环境缺 W8A8 权重*：本机只有 BF16 模型，按教程 05 用 AMCT block 粒度量化生成；CANNJudge 首次提交返回"不在该小组中"，按前端接口加入哈尔滨工业大学 CANN 兴趣小组后复验通过。
2. **AI 辅助说明**：使用了 Qoder CLI（AI 编程助手）辅助：移植原型代码到教程模板、生成 msprof 解析脚本、整理本报告。AI 曾引入一处 tiling 核间切分未对齐的隐蔽 bug（表现为 N=6144 部分元素错误），通过缩小复现矩阵（固定 K 扫 N）定位。所有 AI 产出均由本人以逐元素位级比对（INT32==torch float64 golden、BF16 maxdiff=0）与 CANNJudge 24 用例独立验证，未采信任何未经复算的结论。
3. **优化策略**：① tiling host 端缓存（消除 decode 重复求解）；② AIV 反量化按 1024 条带 + 双缓冲在 2 个 AIV 核交错，UB 预算控制在 7168 元素内避免溢出；③ 多核切分对齐重算提升 Cube 利用率。效果：单算子 decode 小 case 15–22 μs，模型端到端 decode 平均 35.65 ms（<100 ms）。后续可做：将反量化移入 epilogue 融合以消除 GM INT32 中转（预计可追平内置算子）。
