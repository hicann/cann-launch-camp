三、方案说明
3.1 设计思路
算子由 host 调度与 device kernel 两部分组成。

Tiling 设计：tilingData 包含 TCubeTiling（由 MultiCoreMatmulTiling 生成）以及 isPertoken、workspaceSize 两个字段。host侧 CalcQmmTiling 按以下策略确定核组数：以 AIC 总数 / 3 为上限（本平台混合核编译下每个核组由 1 个 Cube 核 + 2 个 Vector 核组成），同时不超过 M×N 按 128 分块后的块数，并在 m、n 两个方向枚举能整除分块数的组合，取不超过上限的最大核组数，保证各核负载均匀、无空跑核；固定分片 SetFixSplit(128,128) 生成失败时回退为自动分片。

Kernel 实现：核函数使用 __global__ __mix__(1,2) 混合编译，入口处 REGIST_MATMUL_OBJ 注册 Matmul 对象。关键设计：

C 矩阵落 UB（VECIN）而非直接写 GM：Cube 算出的 int32 部分和停留在 UB，由同核组的 Vector 单元接着做反量化，避免跨核读写 GM 的同步开销与竞态。通过 mm_.Iterate<true>() + GetTensorC<true> 逐 base block 同步取回；
NZ 格式 B 矩阵寻址：权重按 FRACTAL_NZ 分形布局存储，GlobalTensor 切片偏移按物理布局换算为 n1 * (K/16) * 512 + 列内偏移；
per-token 反量化：逐行执行 int32→fp32→乘 scale→乘 pertoken→转 bf16→写 GM；行数非 8 倍数时 per-token scale 退化为标量读取；操作间用 PipeBarrier<PIPE_ALL> 串行化，避免与 Matmul 库内部事件冲突；
KFC workspace：Matmul 高阶库需要 KFC workspace，使用 aclrtMalloc(ACL_MEM_MALLOC_HUGE_FIRST) 分配 32MB 大页内存并跨调用静态复用，失败时回退 torch 内存。


3.2 问题解决与优化策略
（1）遇到的问题

kernel 启动失败 ret 107000：最初用 at::empty 分配 KFC workspace，普通 device 内存不满足 2MB 大页对齐导致启动失败，改用 aclrtMalloc(ACL_MEM_MALLOC_HUGE_FIRST) 并静态复用后解决；
编译错误若干：host tiling 与 typedef 中 TPosition/CubeFormat 的命名空间用法不一致、MultiCoreMatmulTiling 需传引用等，逐一根据报错修正；
Profiler 测试脚本报 IndexError：kernel_details.csv 中存在缺少 Input Shapes 字段的行，在解析脚本中增加字段防护后解决。
（2）AI 辅助使用情况

本次实践使用了 AI 工具辅助。主要用途：一是辅助理解 Ascend C 混合核编程模型、Matmul tiling API 与 FRACTAL_NZ 内存布局等概念；二是辅助定位上述 107000 workspace 对齐问题和 Profiler 解析问题。

AI 生成的代码并非全部可用：曾出现 host/device 侧类型命名空间用法不一致导致编译失败、反量化逻辑与 Matmul 库内部事件冲突的隐患等问题。本人通过逐条阅读编译报错、对照官方样例、并在 NPU 上实际运行各规格精度测试进行验证，最终提交的代码均经过本人编译、运行与正确性确认。心得：AI 适合用来解释概念和缩小排查范围，但关键设计决策和每个问题的最终验证必须自己完成，否则很难在报错时独立定位。

（3）性能优化策略

通过核组数搜索策略（见 3.1）替代固定核数，使各规格矩阵尽可能打满核组且负载均匀；
采用 SetFixSplit(128,128) 固定分片并验证效果，失败时回退自动分片；
