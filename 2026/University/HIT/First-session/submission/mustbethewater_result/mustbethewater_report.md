## 三、方案说明

### 3.1 设计思路

本项目围绕 QmmCustom 自定义算子的开发展开，目标是在 Ascend AI 处理器上实现适用于大语言模型推理场景的 INT8 量化矩阵乘法，并完成模型接入与功能验证。

整个实现主要包括三个部分：TilingData 设计、Tiling 参数计算以及 Kernel 实现。

首先，Host 端根据输入矩阵的 Shape 计算对应的 Tiling 参数，包括矩阵尺寸、分块信息以及多核任务划分方式，并将这些参数封装到 TilingData 中传递给 Device 端。随后，Kernel 根据这些参数完成数据搬运、矩阵计算以及结果写回。最终，计算结果返回给上层模型，参与后续推理过程。

### 3.2 TilingData 与 Tiling 实现

为了提高矩阵计算效率，本项目采用了 Tiling 技术对输入矩阵进行分块处理。由于片上缓存容量有限，如果直接处理大规模矩阵，将导致频繁的数据搬运，从而降低计算效率。因此，合理的 Tiling 策略对于提升算子性能具有重要意义。

在实现过程中，Host 端首先读取输入矩阵的维度信息，根据矩阵大小动态计算分块参数，并生成对应的 TilingData。随后，Kernel 根据这些参数完成各计算块的调度，实现不同 Shape 下的自适应计算。

Tiling 主要完成以下工作：

- 获取输入矩阵 Shape；
- 计算合适的 Tile 大小；
- 划分 AI Core 计算任务；
- 生成 Kernel 所需参数；
- 将参数传递至 Device 端。

采用动态 Tiling 后，不同规模的矩阵均能够采用较合适的分块策略，在保证计算正确性的同时，提高了 AI Core 的利用效率，并减少了不必要的数据搬运。

### 3.3 Kernel 实现

Kernel 是整个算子的核心部分，其主要职责是完成 INT8 矩阵乘法计算，并输出对应结果。

Kernel 启动后，首先读取 Host 端传递的 Tiling 参数，对计算任务进行初始化。随后，根据分块信息将输入数据从 Global Memory 搬运到 Local Buffer，在片上缓存完成矩阵乘法计算，最后再将计算结果写回 Global Memory。

整个执行流程包括以下几个步骤：

1. 初始化 Kernel 环境；
2. 读取 Tiling 参数；
3. 将输入矩阵搬运至片上缓存；
4. 调用 AI Core 完成矩阵乘法计算；
5. 将计算结果写回输出缓冲区；
6. 返回计算结果供模型继续推理。

此外，Kernel 对不同 Shape 的边界情况进行了处理，保证在各种输入规模下均能够正确完成计算任务，提高了程序的稳定性和可靠性。

### 3.4 问题解决与优化策略

在整个实践过程中，团队先后完成了开发环境搭建、算子开发、功能测试、性能优化以及模型接入等工作，也遇到了一些具有代表性的问题。

（1）开发环境配置

项目初期，团队在配置 Ascend C 开发环境时遇到了编译依赖、环境变量以及工程构建等问题。通过参考课程资料和官方文档，对开发环境进行了逐项检查，并重新配置相关依赖，最终完成工程编译和运行。

（2）功能验证

算子开发完成后，需要保证不同 Shape 下均能够得到正确结果。团队利用课程提供的测试样例，对输出结果与参考实现进行了逐项比对，并根据测试情况调整 Kernel 实现，最终所有测试均顺利通过。

（3）模型接入

在模型集成阶段，团队重点验证了模型是否能够正确调用自定义算子，并观察模型推理过程是否稳定。经过多轮实验，自定义算子能够正常参与模型推理，模型输出符合预期。

（4）性能优化

结合 Profiling 工具分析结果，团队针对算子执行流程进行了优化，主要包括：

- 减少重复的数据搬运；
- 优化矩阵分块策略；
- 提高 AI Core 计算资源利用率；
- 保证不同 Shape 下的执行稳定性。

经过多轮测试，优化后的 Kernel 在保持计算正确性的前提下，运行效率得到进一步提升，并能够稳定完成课程要求的测试任务。
