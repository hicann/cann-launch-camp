# 封闭评测、公平性与算子优化训练：一点建设性思考

## 1. 问题并不是“要不要隐藏测试数据”

封闭评测有清楚且必要的价值：它保护参赛公平，阻止选手直接硬编码样例，也检验实现是否具备基本的泛化能力。对于决定排名的测试集，隐藏精确输入是合理的。

但如果训练阶段连工作负载的基本轮廓也完全不可见，学习目标就会发生偏移。新人通常尚未形成对 shape、dtype、广播模式和数据搬运成本的敏感性，也没有足够经验从五个耗时数字反推输入结构。此时大量提交是在猜测隐藏分布，而不是练习如何依据工作负载设计 tiling。结果可能仍有竞技性，却未必是最高效的算子工程教学。

## 2. 真实工程通常是 workload-aware 的

大模型时代的算子优化，大多不是为一个完全未知的数学接口寻找唯一最优实现。工程团队往往至少知道：

- 目标模型或模型族；
- 常见 shape、序列长度和 batch 分布；
- dtype、layout、广播关系与对齐特征；
- 推理还是训练，以及吞吐、首 Token 延迟或尾延迟等服务目标；
- 硬件型号、内存预算和上下游融合机会。

这些信息不会降低优化的技术含量，反而使开发者能够有依据地讨论核数、Tile 大小、流水深度、数据复用、静态 UB、融合和专用指令。优秀实现通常是“面向主流工作负载的专用快路径 + 覆盖长尾输入的通用正确路径”，而不是在信息真空中寻找一个对所有情况同样快的 Kernel。

V35B 正是这个架构的缩影：通用广播实现守住语义边界，FP16 中小规模使用 STATIC_HALF，INT8 4K 以内使用 FAST_LIGHT，其他输入安全回退。这里的专业能力不在于记住 4096 这个数字，而在于学会提出假设、限定适用域，并为假设之外的输入留下正确后备方案。

## 3. 完全隐藏对新人尤其不友好

有经验的优化者看到某个测试点随核数或 Tile 改变，可能会联想到启动开销、带宽、流水气泡或广播复用。新人看到的则往往只是分数涨跌。没有代表性输入和 profiler 证据，他们很难建立“输入特征—硬件行为—代码策略”的因果联系，也不容易把一次偶然的高分转化为可迁移经验。

封闭环境还会放大测量噪声的误导。V35B 的同字节两次评测相差 5.85 分，TP3 相差 1.22 μs。如果看不到重复测量或分布统计，参赛者可能把环境波动误认为代码收益，进而沿错误方向继续优化。

## 4. 更适合训练的分层评测方案

公平与教学并不冲突，可以通过分层设计同时实现：

1. **公开代表性训练集**：提供若干真实 shape、dtype 和广播模式，允许本地运行与 profiling，用于学习 tiling、流水和数据复用。
2. **隐藏泛化集**：覆盖公开分布的合理变体，检查实现是否过度贴合单个样例以及通用回退是否可靠。
3. **最终防硬编码集**：完全隐藏精确输入，仅用于排名和反作弊。
4. **公开聚合元数据**：不泄露样例值，但披露 shape 区间、dtype 占比、广播类别、对齐比例和各类权重。
5. **稳定性报告**：对微秒级任务进行多次测量，展示中位数、离散度或置信区间，而不是只返回一次耗时。

这种机制仍然不能让选手对着答案硬编码，却能让他们在接近真实工程的条件下形成数据敏感性。排名也会更有解释力：获胜者优化的是被明确描述的目标工作负载，同时还通过隐藏集合证明了泛化和正确性。

## 5. 我希望训练最终教会什么

算子开发训练最值得培养的，不是猜中隐藏测试点，而是下面这条完整链路：

> 观察工作负载 → 建立硬件成本模型 → 设计专用路径 → 用 profiler 和对照实验验证 → 保护通用回退 → 在新分布上检查泛化。

隐藏最终输入仍然重要，但“知道输入形式”不等于“知道答案”。适量公开工作负载信息，能把竞赛从参数猜谜转变为有证据的工程决策，也更贴近未来大模型算子优化的主流实践。
