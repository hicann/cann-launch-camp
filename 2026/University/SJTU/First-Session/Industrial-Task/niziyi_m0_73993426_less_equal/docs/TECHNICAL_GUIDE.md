## 1. 核心概念

### 1.1 Ascend NPU 架构

```
┌─────────────────────────────────────────────┐
│              Ascend 910B NPU                 │
├─────────────────────────────────────────────┤
│  AI Core (AIC)                               │
│  ├── AI Vector Core (AIV) - 向量计算        │
│  ├── AI Cube Core (AIC) - 矩阵计算          │
│  └── Unified Buffer (UB) - 片上内存         │
├─────────────────────────────────────────────┤
│  Global Memory (GM) - 全局内存              │
└─────────────────────────────────────────────┘
```

### 1.2 关键概念

| 概念 | 说明 |
|------|------|
| **GM** | 全局内存，大容量但访问延迟高 |
| **UB** | 统一缓冲区，片上内存，访问快但容量有限 |
| **AIV** | AI 向量核心，执行向量运算 |
| **TPipe** | 流水线管理器，协调数据搬运和计算 |

## 2. 数据类型处理

### 2.1 int32 精确比较

**问题**：int32 无法精确转换为 float32

**解决方案**：使用整数关系
```
x1 <= x2  ⇔  max(x1, x2) == x2
```

### 2.2 int8 处理

int8 范围 [-128, 127]，可被 half 精确表示：

```cpp
// int8 → half → Compare
AscendC::Cast(x1Half, x1, ...);
AscendC::Compare(mask, x1Half, x2Half, CMPMODE::LE, ...);
```

## 3. 广播模式

### 3.1 LINEAR 模式

适用：合并后只有一维

优化要点：
- 连续切分
- 最少元数据

### 3.2 REUSE 模式

适用：[1,N] vs [M,N] 广播

优化要点：
- 广播向量只读一次
- 驻留 UB，减少 GM 流量

## 4. 性能优化技巧

### 4.1 TPipe 外移

将 TPipe 从类成员移到 Kernel 入口，可改善代码布局。

### 4.2 Double Buffer

```cpp
TQue<QuePosition::VECIN, 1> queue;  // 深度为 1
pipe.InitBuffer(queue, 2, bytes);   // Buffer 数为 2
```
