# LessEqual 优化历程：从通用正确性到热点专用路径

> 平台：Ascend 910B / CANN 9.0.1
>
> 冻结版本：V35B
>
> 最终成绩：79.23 分，第 1 名
> 最终测试点：2.14 / 4.52 / 10.16 / 2.36 / 15.78 μs

## 1. 我解决的不是一个比较表达式

`x1 <= x2` 的数学语义很短，算子实现却同时受广播、尾块、数据类型、核间切分、UB 容量和流水同步影响。对于微秒级任务，Host tiling、`TPipe` 初始化和一次多余的 `Duplicate` 都可能与真正的向量计算同量级。因此本项目始终遵循三个原则：

1. 通用路径负责正确性边界，专用路径只覆盖能够严格证明的热点形状；
2. 每个版本尽量只回答一个性能问题，回归后能明确撤销哪一项假设；
3. 封闭评测存在噪声，结论必须同时得到代码路径解释和重复测量支持。

## 2. 基线到 V24：先建立可优化的结构

早期版本首先补齐四种 dtype、标准广播、空张量和非 32 字节对齐尾块。Host 将相邻且广播模式相同的维度合并，并把执行归约为四种运行模式：

| 模式 | 场景 | 关键收益 |
|---|---|---|
| `LINEAR` | 同形状或合并后的一维输出 | 连续寻址，去掉广播坐标换算 |
| `ROW` | 一般高维广播 | 一次处理完整内层行，降低索引更新频率 |
| `REUSE_X1` | `[1,N]` 与 `[M,N]` | x1 Tile 驻留 UB，跨行复用 |
| `REUSE_X2` | `[M,N]` 与 `[1,N]` | x2 Tile 驻留 UB，跨行复用 |

V14–V24 的重点是把流水结构稳定下来：`TPipe` 生命周期外移，多 Tile 的 LINEAR 路径使用双缓冲，并把全 1 Tensor 从每个 Tile 的重复生成变为预生成复用。这个阶段的收获不是某个孤立参数，而是形成了后续可以安全分叉的通用 Kernel。

## 3. V30a：编译期分离调度开销

V30a 将运行时分支提升为 TilingKey 模板参数，形成最初两种编译期调度：

- `SCH_NORMAL`：单缓冲通用路径，避免小任务承担双缓冲固定成本；
- `SCH_LINEAR_DB_ONES`：仅在 LINEAR 且每核工作量超过 Tile 长度时启用双缓冲，并预生成 ones。

同时，小型 LINEAR（总元素不超过 128）采用每核 32 元素、最多四个有效核的策略；较大的严格同形状 FP16/INT8 则使用更积极的 AIV 并行。V30a 已经证明：同一个“比较算子”内部，小任务启动开销与大任务吞吐需要不同答案。

## 4. V33：FAST_LIGHT 验证轻量专用 Kernel

V33 引入 `SCH_FAST_LIGHT`，目标是严格同形状、单段可完成的小型热点。它去掉通用广播状态和多 Tile 队列管理，只保留 GM→UB、比较和 UB→GM 的必要链路。

实验说明轻量 Kernel 的方向有效，但也暴露出一个重要问题：按 dtype 共用过宽的触发范围，会让原本占优的路径承担新实现的固定成本。专用路径只有在“适用集合足够窄”时才是真正的优化。

## 5. V34：STATIC_HALF 攻克 FP16 中小规模

V34 为严格同形状 FP16、129–16384 元素增加 `SCH_STATIC_HALF`。这条路径直接使用静态 UB `LocalTensor`，调用 `InitSocState()`，并用 HardEvent 建立明确的搬入、向量计算和搬出依赖：

- `MTE2_V`：GM→UB 完成后允许 Vector 读取；
- `V_MTE3`：Vector 写完结果后允许 UB→GM；
- `MTE3_MTE2`：上一轮搬出结束后复用静态 UB。

Host 根据总长度选择每核目标工作量 32、128、256 或 512，避免所有规模机械使用同一核数。V34 将 TP1、TP3、TP4 明显压低，但 TP2、TP5 出现退化。这是一个有用的诊断信号：STATIC_HALF 命中了部分热点，却不能解释全部隐藏工作负载。

## 6. V35A：用“关闭快路径”定位回归

V35A 没有急着继续叠加技巧，而是关闭 FAST_LIGHT 做消融实验。结果为 2.28 / 5.30 / 10.60 / 2.92 / 16.32 μs：TP4 明显退化，而 TP2、TP5 没有恢复到理想水平。

这个版本的价值在于排除了“FAST_LIGHT 整体有害”的假设。问题不是是否保留轻量路径，而是它应该服务哪一种 dtype、哪一段规模。消融实验把下一步搜索从整个 Kernel 缩小到了触发条件。

## 7. V35B：将 FAST_LIGHT 收窄到 INT8 4K

V35B 的最终改动很克制：

- FP16 的 129–16384 元素继续交给 `SCH_STATIC_HALF`；
- `SCH_FAST_LIGHT` 只用于严格同形状 INT8，且总元素为 129–4096；
- 其他场景保持 V30a 已验证的 `SCH_NORMAL` 或 `SCH_LINEAR_DB_ONES`；
- 四种调度值通过 2-bit UINT 模板字段生成独立二进制。

这不是把某个测试点写进代码，而是根据 dtype 的计算链路做架构分工：INT8 需要精确 Cast 到 half 后再比较，小型单段执行更容易从轻量控制流中获益；FP16 则更适合静态 UB 与显式事件同步。

## 8. 同字节重复评测：如何看待微秒级噪声

V35B 两次提交的代码逐字节相同，结果却有明显差异：

| 测试点 | 首次 | 重复评测 | 差值 |
|---|---:|---:|---:|
| TP1 | 2.08 μs | 2.14 μs | +0.06 μs |
| TP2 | 5.30 μs | 4.52 μs | -0.78 μs |
| TP3 | 11.38 μs | 10.16 μs | -1.22 μs |
| TP4 | 2.40 μs | 2.36 μs | -0.04 μs |
| TP5 | 16.60 μs | 15.78 μs | -0.82 μs |
| 分数 | 73.38 | 79.23 | +5.85 |

因此，单次榜单数字不能独立证明某项优化。可靠判断至少需要：冻结提交内容、记录各测试点、重复测量，并检查变化能否由实际触发的代码路径解释。V35B 被选为最终版本，不只因为第二次排名第一，也因为它保留了 V34 的 FP16 优势，并用窄化的 INT8 热点路径修复了 V35A 揭示的问题。

## 9. 最终可复用经验

- 先按广播结构划分执行模式，再按 dtype 和规模细化调度；
- 小算子的第一优化对象往往是固定开销，而非向量指令本身；
- 编译期分离可以保护已赢下的路径，避免运行时分支和无关状态渗入；
- 专用 Kernel 的触发条件应当可证明、可回退、可单独撤销；
- 黑盒评测中，消融实验和同字节复测比继续堆参数更有信息量；
- 最终实现应始终保留通用正确性后备路径。

这段优化经历最重要的变化，是从“猜一个更快的参数”转向“建立一个可以被下一次实验证伪的模型”。排名是结果，能复用的方法才是成果。
