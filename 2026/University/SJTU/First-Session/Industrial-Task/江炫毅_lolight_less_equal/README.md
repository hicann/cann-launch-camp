# Ascend C LessEqual 算子

## 项目说明

本项目使用 Ascend C 实现 `LessEqual` 自定义算子，在昇腾 NPU 上逐元素判断 `x1 <= x2`，输出布尔张量。

实现面向 `ascend910b`，支持同形状计算、非 32 字节对齐数据、空张量以及 NumPy/TensorFlow 风格广播。

## 功能定义

对于广播后的每个输出位置 `i`：

```text
y[i] = (x1[i] <= x2[i])
```

输入要求：

- `x1` 与 `x2` 的数据类型必须相同。
- 支持 `float16`、`float32`、`int32`、`int8`。
- 输入格式为 `ND`。
- 两个输入形状必须满足标准广播规则：从最右侧开始，各维相等或其中一维为 `1`。
- 不兼容的广播维度在 Shape 推导和 Tiling 阶段返回失败。

输出：

- 数据类型始终为 `bool`。
- 输出形状为两个输入广播后的形状。
- 比较结果要求完全准确。

## 实现架构

### 1. 双执行路径

Host 根据输入形状选择执行模式：

- `mode = 0`：两个输入形状完全相同，直接走连续内存快速路径。
- `mode = 1`：输入需要广播，按照压缩后的维度、stride 和行状态执行。

同形状路径避免广播索引计算；广播路径按行处理，减少逐元素坐标换算。

### 2. 分数据类型调度

同形状场景根据数据类型采用不同多核策略：

- `float16`、`int8`：在 32 元素边界上尽量使用可用 AIV 核。
- `float32`、`int32`：以 8192 元素为目标工作量分配核心，避免小任务过度并行。
- 广播场景：以 2048 个输出元素为目标工作量分配核心，再按连续行划分任务。

该策略用于平衡核心启动开销与并行计算收益。

### 3. 向量计算

各数据类型的核心计算路径如下：

- `float16`、`float32`：直接使用向量 `Compare(..., CMPMODE::LE)`。
- `int32`：利用 `min(x1, x2) == x1` 等价实现小于等于比较。
- `int8`：先向量转换为 `half`，再执行向量比较。

比较产生的 mask 通过 `Select` 展开为 `0/1`，随后转换为 `int8` 形式的布尔输出。

### 4. 广播处理

广播模式将维度压缩为外层行和连续末维：

- stride 为 `0` 表示该输入在对应维度广播。
- 末维标量广播通过 `Duplicate` 在 UB 中展开。
- `InitRowState` 计算每个核心首行的输入偏移。
- `AdvanceRowState` 以状态递增方式更新后续行偏移。

这样可避免对每个输出元素重复执行完整的多维除法和取模。

### 5. UB 与流水

- 输入与输出使用深度为 `2` 的 `TQue`。
- Tile 长度根据数据类型和可用 UB 容量计算，上限为 8192 个元素。
- 数据搬入使用 `DataCopyPad`，兼容尾块非对齐场景。
- Kernel 按 `CopyIn -> Compute -> CopyOut` 完成每个 Tile。

## 构建环境

已验证评测环境：

- CANN 8.5.0
- Ascend C
- 计算单元：`ascend910b`
- CMake 3.16 或更高版本

在已加载 CANN 环境变量且 `find_package(ASC REQUIRED)` 可用时，可执行：

```bash
cd src
mkdir build
cd build
cmake ..
make -j
```

构建系统会生成 Host Tiling 动态库、ACLLN 调用库、Kernel 二进制及自定义算子安装包。

## 设计取舍

本实现以课题正确性和执行性能为主要目标：

- 同形状与广播路径分离，减少热路径分支。
- 对不同数据类型使用差异化核心数量，避免统一满核导致部分场景退化。
- 保留完整向量计算，避免 `GetValue` / `SetValue` 逐元素循环成为瓶颈。
- 不引入额外 workspace。
