# Ascend C LessEqual 自定义算子

## 项目简介

本项目基于 Ascend C 实现高性能 `LessEqual` 自定义算子，运行平台为 Ascend 910B，算子语义与 TensorFlow `tf.math.less_equal` 一致。

算子逐元素判断 `x1 <= x2`，输出布尔张量，并支持 NumPy/TensorFlow 标准广播规则。

```text
y[i] = (x1[i] <= x2[i])
```

## 功能要求

| 项目         | 说明                                  |
| ------------ | ------------------------------------- |
| 输入         | `x1`、`x2`                            |
| 输出         | `y`                                   |
| 输入类型     | `float16`、`float32`、`int32`、`int8` |
| 输出类型     | `bool`                                |
| 数据格式     | ND                                    |
| 输入类型约束 | `x1` 与 `x2` 必须具有相同数据类型     |
| 计算精度     | 严格执行 `<=`，不使用误差容忍         |
| 广播规则     | 与 NumPy/TensorFlow 标准广播语义一致  |
| 目标硬件     | Ascend 910B                           |

## 广播规则

两个输入形状从最右侧维度开始比较。每一维满足下列任一条件时可以广播：

- 两个维度大小相等；
- `x1` 的当前维度为 `1`；
- `x2` 的当前维度为 `1`。

不满足上述条件时，Host 侧返回形状推导或 Tiling 错误。

## 实现架构

### 同形状高速路径

当 `x1` 与 `x2` 的形状完全一致时，算子进入 `mode = 0` 高速路径：

1. Host 根据输出长度和 AIV 核数划分连续数据区间。
2. Kernel 使用 `DataCopyPad` 将连续数据从 GM 搬入 UB。
3. 在 Vector 计算单元上批量完成比较。
4. 将比较掩码转换成 `0/1` 布尔字节。
5. 使用 `DataCopyPad` 将结果连续写回 GM。

该路径避免广播索引计算，适用于大多数同形状张量，是主要性能路径。

### 广播优化路径

当输入形状不同但满足广播规则时，算子进入 `mode = 1`：

1. Host 从右向左计算广播后的形状和输入 stride。
2. 广播维度使用 stride `0` 表示重复读取同一数据。
3. Host 合并可连续访问的相邻维度，减少 Kernel 的有效维数。
4. Kernel 按输出行分核，每个核心处理连续的末维数据。
5. 行索引采用状态递增更新，避免对每个输出元素重复执行完整的除法和取模。
6. 末维广播时使用 `Duplicate` 在 UB 中扩展标量，随后执行向量比较。

当前 Tiling 数据最多保存 `16` 个压缩后的有效维度。

## 数据类型优化

### float16 与 float32

直接使用 Ascend C `Compare(..., CMPMODE::LE, ...)` 执行向量比较。

### int32

使用下式将小于等于转换为 NPU 友好的向量操作：

```text
x1 <= x2  <=>  Min(x1, x2) == x1
```

Kernel 先执行向量 `Min`，再执行向量 `Compare(EQ)`，避免逐元素标量比较。

### int8

先使用向量 `Cast` 将 `int8` 转换为 `half`，再通过 `Compare(LE)` 完成比较。`int8` 的全部取值都能被 `half` 精确表示，因此不会引入比较误差。

## 性能设计

- **多核并行**：根据数据规模和 AIV 核数动态设置 `blockDim`。
- **UB 自适应 Tiling**：根据硬件 UB 容量、数据类型和中间缓冲开销计算 tile 大小。
- **双缓冲队列**：输入和输出队列使用深度 `2`，为搬运与计算流水提供缓冲。
- **连续内存访问**：高速路径和广播末维都尽量保持 GM 连续读写。
- **向量化计算**：四种数据类型均避免通用逐元素比较。
- **广播维度压缩**：合并连续维度，降低索引计算开销。
- **行状态递增**：广播路径只在首行解析坐标，后续行通过进位更新基址。
- **标量广播复用**：广播值搬入 UB 后使用 `Duplicate` 扩展，避免重复访问 GM。
- **非对齐处理**：通过 `DataCopyPad` 支持长度不是 32 字节倍数的输入和输出。
- **空张量处理**：输出元素数为 `0` 时设置安全的单核配置并直接结束。

## 核数调节

Host 文件中包含以下性能调节项：

```cpp
constexpr uint32_t LESS_EQUAL_SLOWDOWN_CORE_DIV = 2;
```

它会主动减少实际使用的核心数：

- 设置为 `1`：不限制核心数，适合追求最高吞吐性能；
- 设置为 `2`：核心数约减半，当前默认值；
- 设置为 `3` 或 `4`：进一步降低并行度。

## 关键 Tiling 字段

| 字段         | 作用                                     |
| ------------ | ---------------------------------------- |
| `totalLen`   | 广播后输出总元素数                       |
| `tileLen`    | 单次 UB 计算的元素数量                   |
| `blockDim`   | 实际启用的 AIV 核数                      |
| `perCore`    | 每核处理的元素数或输出行数               |
| `mode`       | `0` 表示同形状高速路径，`1` 表示广播路径 |
| `ndim`       | 压缩后的广播维数                         |
| `lastDimLen` | 广播路径的连续末维长度                   |
| `totalRows`  | 广播路径的输出总行数                     |
| `outShape`   | 压缩后的输出形状                         |
| `x1Stride`   | `x1` 的广播 stride                       |
| `x2Stride`   | `x2` 的广播 stride                       |

## 测试建议

- **数据类型覆盖**：float16、float32、int32、int8所有支持类型
- **维度场景覆盖**：
- 基础维度：1维、2维、3维、4维（N4,N3,N2,N）
- 高维场景：含批次维度的多维场景（…, N4,N3,N2,N）
- 非对齐场景：N、N2、N3、N4为非32整倍数的内存非对齐场景
- 空张量：零元素张量
- **广播场景覆盖**：
- 标量与张量广播
- 向量与矩阵广播
- 不同形状高维张量广播
- **边界场景覆盖**：
- 极限维度：N=1、N=10000等边界值
- 相等值：x1=x2的边界情况
- 边界数值：数据类型的最小值/最大值比较
- **精度场景覆盖**：
- 正常数值范围：常规比较验证
- 边界数值：接近数据类型边界的比较
- 完全准确：比较运算无误差容忍
